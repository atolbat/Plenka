## v67 + 3.20: подложка (чужой кадр в полях) + «Открыть с помощью»

`plenka-optimized-67.html` — v66 + 16 фиксов по изолированным агентам
(2 прохода: жизненный цикл слоёв VL-1..8 и гонки переключений RC-101..109).
Оболочка 3.19 → 3.20 (versionCode 149). Скрипты: `scripts/patch67.py`,
`scripts/build_apk67.sh`.

**Подложка / «под видео видно другое» (жалоба юзера)**
1. **RC-101/HIGH** — `setVblank` бампал токен только в remote-ветке: устаревший
   `posterFirstMs`-колбэк прежней цели рисовал чужой кадр поверх играющего
   (ветки null/data: не инвалидались). Токен — первой строкой, во всех ветках;
   `snapPoster` тоже бампает (его кадр свежее pending-fetch).
2. **VL-1/HIGH** — в подложку/постер попадал карточный thumb 320×180 с запечённым
   леттербоксом (когда нет fframe): при несовпадении аспектов его поля торчали
   из-под видео. Новый `trueAspectPoster()`: маска — только fframe (снят с
   элемента, композиция совпадает) или серверная /t/ (докажет X-Plenka-FrameT).
   Без кадра — честный чёрный.
3. **VL-2/MED** — кадр подложки жил весь сеанс трека: теперь чистится в момент
   первого показанного кадра (killOld, по токену свапа) и в mirrorStop — поля
   снова чистый чёрный (зум/пан/перезарядка не подставляют устаревший кадр).
4. **RC-102/HIGH** — откат при неудачном открытии шёл по устаревшему `prevIdx`
   (items мутирует за долгую загрузку): подложка/профиль получали ЧУЖОЙ трек.
   Захват по ссылке + пересчёт по факту играющего (`_pid`) ДО setVblank.
5. **RC-103/HIGH** — постер упавшей цели поднимался над возобновлённым треком:
   владение открытием `posterEl._own` + гашение в abort/fail-ветках.
6. **VL-4/MED** — abort-ветка: постер/freeze недооткрытой цели висели над
   возобновлённым треком бессрочно (hidePosterSoon был убит showPoster).
7. **VL-3/MED** — chase-PiP: freeze момента входа в окно не снимался никем
   (навсегда перекрывал страницу поверх зеркала) — hideFreeze на входе в chase.
8. **VL-5/MED** — chase: бокс Y (элемент окна) участвовал в гонке DOM-порядка

**Гонки переключений**

## v65 + 3.18: аудит-фиксы — XSS, токен моста, tfdt/trex, гонки удалений, PiP из мини

`plenka-optimized-65.html` — v64 + 44 фикса по итогам внешнего аудита
(3 изолированных агента + живой смоук). Оболочка 3.17 → 3.18 (versionCode 147).
Скрипты: `scripts/build65.py` (HTML из v64, якоря с проверкой), `scripts/patch65.py`
(натив), `scripts/mock65.py` (стенд с XSS-регрессией, item id=5).

**Безопасность**
1. **Stored XSS закрыт** («расширение» имени файла в фильтре и в «о файле»
   вставлялось в innerHTML без esc — воспроизведён PoC на файле
   `clip.mp4<img src=x onerror=…>`). Теперь esc на обеих подстановках.
2. **Токен локального моста**: loopback 127.0.0.1 на Android общий для всех
   приложений — любое соседнее читало `/list` и выкачивало медиатеку без прав.
   Теперь данные (/v,/a,/c,/t, списки) отдают 404 без `tok=` (SecureRandom,
   filesDir/srvtoken, странице — через `?tok=`; URL в IDB мигрируют на старте).
3. **Cleartext** — только 127.0.0.1 (network security config) вместо глобального флага.
4. **Пароли keystore из git убраны** (`PLENKA_KS_*` из окружения; в истории
   репозитория пароль оставался — сменить пароль ключа).

**Логика воспроизведения (переключения/фантомы/гонки)**
5. **tfdt** — версия/BMDT читались со сдвигом +4 байта: карта якорей байт→время
   была мусорной на tfdt v0 (дефолт ffmpeg) — сик систематически промахивался и
   уводил мост в recover/фолбэк («сик 200 → 2992»). Подтверждено синтетикой.
6. **trex** — дефолты сэмплов читались со сдвигом -4 (dur=desc, size=dur, flags=size).
7. **msebPatchMoof** — пропущенный шаг default_sample_duration (fl&0x000008).
8. **msebPrevMoof** — размер moof читался из ASCII 'moof' (~1.8 млрд): проверка
   «после moof идёт mdat» не срабатывала никогда.
9. **Качалка** — смерть pump по сетевому исключению больше не оставляет мост
   навсегда без подкачки (→ recover); msebFetch — таймаут 10с + ретрай (6 зависших
   фетчей параличили всю сеть к 127.0.0.1); кап 3 полных пересозданий моста на файл
   (раньше «ядовитый» фрагмент гонял цикл сброс→reopen бесконечно); сик при
   неудаче поиска байта больше не «садится» молча в начало файла.
10. **currentIdx по ссылке** во всех точках удаления (крестик, bad, lib-sync,
    рескан медиатеки, рескан SAF-реестра, рескан папки): позиция играющего больше
    не записывается в чужой файл, next/prev не прыгают.
11. **savePos** — гвард «активный элемент владеет треком currentIdx»: время
    уходящего больше не пишется в позицию нового при «назад»/pagehide в окне
    переключения.
12. **PiP из мини** — живой элемент возвращается в #stage до pipEnter (и на кнопке,
    и на авто-PiP): окно PiP показывает видео, а не стоп-кадр/чёрное.
13. **Мини после soft-close** — панель пересаживает уже новый активный элемент
    (кадр и звук одного трека, вместо кадра A + звука B).
14. **swapRoles** — оконное PiP уходит за новым активным; seek-таймеры уходящего
    сбрасываются; после неудачного открытия возвращается игра уходящего трека.
15. **Папки в drag&drop** — readEntries порциями (раньше >100 файлов обрезались молча).
16. **Поток-вочдог** работает и в мини-панели; пауза — такт качалки 1с;
    MessageChannel-сон — с микро-паузой (фон не крутит busy-spin).

**Хранилище/прочее**
17. idbOK реанимируется успешной транзакцией (одна ошибка больше не отключает
    сохранение до перезагрузки); localStorage в try в bgPauseGated; objectURL пробы
    отзывается в catch; дубли objectURL в превью карточки; postMessage — только
    самовызов; inflight-импорты ≤2.
18. **Оболочка**: фолбэк порта 8978–8986 (занятый 8977 больше не даёт вечный
    «чёрный экран»), атомарный picked.json, счётчик читателей ovh-дескрипторов
    (закрытие под pread больше не рвёт отдачу), двойной close fd в serveAfd
    устранён (Os.lseek+pread), MediaSession активна с первой игры, цикл диалогов
    прав остановлен, POST_NOTIFICATIONS спрашивается один раз после 20с игры,
    WakeLock 5мин с автопродлением.

## Главное в 3.13 / v59: сворачивание без паузы ВООБЩЕ + автоплей, который не умирает

Разобрал репорт на 3.12 (два журнала ДИАГ): «сворачиваю — пауза слишком
долгая, отмена паузы очень слышно»; «периодически просто запускаю видео —
кадр с первого видео висит надолго, само не играет, пока вручную плей не
нажму».

1. **Фоновая пауза — причина была НЕ в странице.** Chromium гасит
   `<video>` на скрытой странице: цепочка по исходникам Chromium —
   `View.onWindowVisibilityChanged(GONE)` при уходе активити →
   `AwContents.setWindowVisibilityInternal → updateWebContentsVisibility` →
   `document.hidden=true` → авто-пауза медиа. Сторож страницы не может
   выиграть эту войну в принципе (3 попытки v58 оставались заиканием).
   Натив 3.13: **PlenkaWebView** — единственный колбэк, через который
   WebView узнаёт о скрытии, передаёт в Chromium `VISIBLE`, пока играет
   медиа (проверенный хак SO 52028940/53723297; не в PiP). Итог: свернули
   — звук идёт ровно, БЕЗ единой паузы. Пауза юзером (шторка/страница) →
   `mediaUpdate → refreshBgPolicy()` — обман снят, страница честно спит.
   Плюс `setRendererPriorityPolicy(RENDERER_PRIORITY_IMPORTANT, false)`.
   3-попыточный сторож из v58 остался страховкой на случай OEM-причуд.
2. **Автоплей умирал от крестика мини-панели.** `miniClose` делал
   `playToken++` и СЫРУЮ `video.pause()`: любой open в полёте тихо
   умирал (lsWhy='race', play() не вызывался) — плеер с постером стоял до
   ручного плей («кадр с первого видео висит»). На устройстве юзер ходил
   циклом «открыл → медленно → назад → мини → ✕» — каждый ✕ глушил и
   открытие, и тёплый запасной. Теперь: ✕ при открытом плеере с другим
   файлом гасит ТОЛЬКО панель; полный стоп — когда панель и правда всё.
3. **Сырая пауза мини оставляла `bgLive=true`** — сторож фона потом
   «оживлял» уже закрытое юзером видео (лишние пауза/отмена). Теперь
   `stopMini` зовёт обёртку `pause()`: userPaused/bgLive честны.
4. **Страховка автоплея**: через 600мс после play() один повтор, если
   элемент стоит, open актуален и юзер не паузил — лечит любой молчаливый
   AbortError/WebView-каприз. `play()` больше не глотает AbortError
   молча — причина видна в ДИАГ. Событие `playing` и флаги `pa/ld`
   элементов — тоже в ДИАГ (слепых зон больше нет).

## Что смотреть на устройстве

1. Открыть видео, дать первым кадрам пройти, свернуть — звук идёт РОВНО,
   без паузы и без заикания (в logcat: «bg: окно скрыто … страница
   остаётся видимой»).
2. Свернуть, поставить паузу из шторки — звук встал, уведомление живёт;
   «Играть» из шторки — снова идёт (не разворачивая приложение).
3. Открыть видео из библиотеки и ПРОСТО ЖДАТЬ — само играет (до ~1с
   медленнее «горячего» старта). Если вдруг не заиграло — в ДИАГ теперь
   видны: «play() перебит (AbortError)…» (виновник), «автоплей-страховка:
   повторный play()», «событие: playing», элементы с `pa=/ld=`.
4. Цикл юзера «открыл → назад → ✕ мини → открыл другое» — новое видео
   стартует само, тёплый сосед не гибнет.

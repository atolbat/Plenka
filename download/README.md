# ПЛЁНКА native — файлы

## v63: PiP из мини, призрак кадра, «вечные новые», 4К, лента буфера + иконка

`plenka-optimized-63.html` — v62 + пять репортов юзера, новый лаунчер-значок:

1. **PiP из миниплеера — чёрный экран и чужой интерфейс.** Из открытого
   видео окно PiP показывало видео, из миниплеера — тёмную страницу с
   панелькой (класс `minist` прятал и плеер, и сцену). Теперь PiP из мини
   показывает ТОТ ЖЕ вид: видео в сцене + HUD (play/next/развернуть).
   После выхода из PiP — как до входа: список + мини, видео не прерывалось.
2. **Призрак чужого кадра.** После цикла «PiP из мини → закрыл PiP →
   закрыл видео крестиком мини → открыл другое» под новым видео до его
   первого кадра просвечивал кадр ПРОШЛОГО: подложка `vblank` чистилась
   только при выходе из плеера кнопкой, но не крестиком мини. Теперь
   `stopMini` чистит подложку/маску/постер — симметрично выходу из плеера.
3. **«Новое» у всех видео при каждом рестарте.** Синк медиатеки
   (onPageFinished) обгонял чтение реестра из IndexedDB: все файлы
   пересоздавались с меткой «новое» и позицией 0 — затирая и «смотреть
   с момента». Теперь слияние с медиатекой гейтится готовностью реестра
   (REG_READY, гейт в самом natvMerge — покрывает и вочдог, и форс-мердж),
   придержанный синк догоняет после чтения.
4. **4К.** Цель буфера для высокого разрешения (≥2560×1440 или >4МБ/с):
   до 50МБ / 8–24с запаса вместо 18МБ / 6–14с (у 4К фактически было 6с) +
   качалка спит 60мс вместо 140мс — буфер не отстаёт от декодера.
5. **Индикация подгрузки на линии перемотки убрана** — светлых полос
   «что подгрузилось» больше нет (по репорту).

**Иконка v4:** Ё (Unbounded 800, кремовая) + янтарные шашки-перфорация
плёнки с двух сторон, тёплый чёрный фон. Квадратная и круглая версии
во всех плотностях mipmap.

## v61: три бага основного приложения (репорт)

`plenka-optimized-61.html` — v59 + три фикса, ничего нового не привнесено:

1. **Флэш скрытых при старте.** Оболочка на onPageFinished сразу толкает
   синк (скан медиатеки) — он приходил раньше, чем страница дочитывала
   hiddenlist из IndexedDB, и на мгновение рисовались ВСЕ видео, включая
   приватные. Теперь список и лента не рендерятся, пока hiddenlist не
   прочитан (гейт `hiddenReady`); скелетон остаётся, приватность цела.
2. **Свайп назад из приватного видео → публичная папка.** Системный
   «назад» при открытом плеере выходил из скрытого раздела вместо
   закрытия плеера. Теперь плеер проверяется первым: «назад» закрывает
   видео (в мини-панель), раздел остаётся скрытым; выход из раздела —
   следующим «назад», как раньше.
3. **Битые плейсхолдеры аудио без обложки.** Мини-панель, очередь и
   remote-мини ставили сетевую обложку `/t/…` прямо в `<img>`: 404
   (нет встроенного арта) рисовал «битое изображение». Теперь любая
   сетевая обложка в DOM помечена `data-fb` и при ошибке меняется на
   плейсхолдер (нота/заглушка), 404 запоминается и не долбится.

## dev-ветка: эксперимент WebGL (v60)

`plenka-optimized-60.html` — рендер **видео** через WebGL/Canvas (эксперимент):
`<video>` остаётся декодером (MSE-мост, PiP, фоновое воспроизведение, сторожа —
как были), презентацию кадра берёт canvas-слой `#vgl`: WebGL-текстура + шейдер,
фолбэк на 2D-канвас, затем на родной `<video>`. Плёночная градация с виньеткой —
`localStorage plenka.vglfx='1'` (по умолчанию выкл). Выключить слой:
`localStorage plenka.vgl='off'` или `?vgl=off`; принудительный 2D — `?vgl=2d`.
Состояние — в ДИАГ, строка «рендер видео (эксперимент)». В APK пока не собирается.

## Главное в 3.13 / v59: сворачивание без паузы ВООБЩЕ + автоплей, который не умирает

Разобрал репорт на 3.12 (два журнала ДИАГ): «сворачиваю — пауза слишком
долгая, отмена паузы очень слышно»; «периодически просто запускаю видео —
кадр с первого видео висит надолго, само не играет, пока вручную плей не
нажму».

1. **Фоновая пауза — причина была НЕ в странице.** Chromium гасит
   `<video>` на скрытой странице: цепочка по исходникам Chromium —
   `View.onWindowVisibilityChanged(GONE)` при уходе активити →
   `AwContents.setWindowVisibilityInternal → updateWebContentsVisibility` →
   `document.hidden=true` → авто-пауза медиа. Сторож страницы не может
   выиграть эту войну в принципе (3 попытки v58 оставались заиканием).
   Натив 3.13: **PlenkaWebView** — единственный колбэк, через который
   WebView узнаёт о скрытии, передаёт в Chromium `VISIBLE`, пока играет
   медиа (проверенный хак SO 52028940/53723297; не в PiP). Итог: свернули
   — звук идёт ровно, БЕЗ единой паузы. Пауза юзером (шторка/страница) →
   `mediaUpdate → refreshBgPolicy()` — обман снят, страница честно спит.
   Плюс `setRendererPriorityPolicy(RENDERER_PRIORITY_IMPORTANT, false)`.
   3-попыточный сторож из v58 остался страховкой на случай OEM-причуд.
2. **Автоплей умирал от крестика мини-панели.** `miniClose` делал
   `playToken++` и СЫРУЮ `video.pause()`: любой open в полёте тихо
   умирал (lsWhy='race', play() не вызывался) — плеер с постером стоял до
   ручного плей («кадр с первого видео висит»). На устройстве юзер ходил
   циклом «открыл → медленно → назад → мини → ✕» — каждый ✕ глушил и
   открытие, и тёплый запасной. Теперь: ✕ при открытом плеере с другим
   файлом гасит ТОЛЬКО панель; полный стоп — когда панель и правда всё.
3. **Сырая пауза мини оставляла `bgLive=true`** — сторож фона потом
   «оживлял» уже закрытое юзером видео (лишние пауза/отмена). Теперь
   `stopMini` зовёт обёртку `pause()`: userPaused/bgLive честны.
4. **Страховка автоплея**: через 600мс после play() один повтор, если
   элемент стоит, open актуален и юзер не паузил — лечит любой молчаливый
   AbortError/WebView-каприз. `play()` больше не глотает AbortError
   молча — причина видна в ДИАГ. Событие `playing` и флаги `pa/ld`
   элементов — тоже в ДИАГ (слепых зон больше нет).

## Что смотреть на устройстве

1. Открыть видео, дать первым кадрам пройти, свернуть — звук идёт РОВНО,
   без паузы и без заикания (в logcat: «bg: окно скрыто … страница
   остаётся видимой»).
2. Свернуть, поставить паузу из шторки — звук встал, уведомление живёт;
   «Играть» из шторки — снова идёт (не разворачивая приложение).
3. Открыть видео из библиотеки и ПРОСТО ЖДАТЬ — само играет (до ~1с
   медленнее «горячего» старта). Если вдруг не заиграло — в ДИАГ теперь
   видны: «play() перебит (AbortError)…» (виновник), «автоплей-страховка:
   повторный play()», «событие: playing», элементы с `pa=/ld=`.
4. Цикл юзера «открыл → назад → ✕ мини → открыл другое» — новое видео
   стартует само, тёплый сосед не гибнет.
